# CuttleX 功能性开发方向（2026-08 确认）

> 已确认的开发方向，按批次推进。首批：**操作体验优化（全选/拖拽/二维码）+ 移动端适配**；随后：**节点回国链路测速（三网 IP）**、**审计日志**。

## ✅ 确认方向

### P0 操作体验优化（本批）

1. **节点库批量操作**：多选（全选/反选）、批量改备注/分组/启用停用/删除。
2. **规则链拖拽排序**：拖拽调整规则顺序；临时停用（保留配置不删除）；复制规则。
3. **节点二维码**：节点详情/行内二维码，手机扫码导入。

### P1 移动端适配

- 节点表格/编辑抽屉在窄屏下的可用性：卡片化列表、触屏操作、编辑抽屉全屏化。

### P2 节点回国链路测速（国内三网视角）

**目标**：衡量节点对国内用户的真实可用性 —— **节点出发 → 国内三网固定 IP（TCP 握手 RTT）**。

- 默认目标：电信 `202.96.209.5`、联通 `210.22.97.1`、移动 `211.136.15.100`，以及阿里 DNS `223.5.5.5`、腾讯 DNS `119.29.29.29`（可配置）。
- **禁止**：从 Cloudflare Worker（海外边缘）直接 ping 节点 —— 那是海外视角，对国内用户无参考价值，不做。
- **实现路径**：Worker 通过节点自身协议建立隧道（SOCKS5 / HTTP 代理协议节点可行），从**节点出口**发起对国内三网 IP 的 TCP 握手测 RTT；节点可连通性（tcp ping 节点 IP:port）作为辅助指标单独展示。
- **协议覆盖边界**：SS/VMess/VLESS 等加密隧道协议无法在 Worker 内实现完整客户端，先只对 SOCKS/HTTP(S) 节点做真实隧道测速，其余节点仅显示"海外连通性探测"并明确标注视角。
- 测速结果落库：单次、平均、丢包；订阅输出可选"排除超时/高延迟节点"。

### P3 审计日志（问题待答后细化）

**能审计的内容**（CuttleX 是自托管管理工具，不承载用户流量）：

- 管理操作：登录成功/失败、订阅创建/编辑/删除/轮换 token、节点导入/编辑/删除、集合变更、远程源抓取结果。
- 订阅交付：每次 token 拉取的时间、来源 IP（脱敏）、User-Agent、近 N 次历史 → 发现订阅地址泄漏/盗用。

**无法审计的内容**：

- 用户通过代理访问了哪些网站 —— CuttleX **不承担流量转发**，客户端直连节点、流量完全在节点与用户之间，工具层面无感知、也不应感知。需要这类能力请用节点/网关侧审计（如代理服务自身日志），不是本产品的边界。

### P4 待定（视反馈）

- 订阅差分 & 变更提醒、定时刷新失败回退、规则模板库、i18n、加密导出备份、TUN 配置导出、凭据加密存储。

## 技术备忘

- 测速依赖 Worker TCP sockets（`cloudflare:sockets` 的 `connect()`），本地 workerd 与线上均可用。
- 三网 IP 为公开固定地址；测速目标可配置，避免给目标造成压力（建议单节点并发 ≤ 5、超时 5s）。
- 审计日志渲染需脱敏（IP 只保留前两段 / 国家+城市级）。
