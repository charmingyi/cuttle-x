# CuttleX 后续功能性更新建议

> 本清单按优先级分组，供项目维护者评估取舍。每条标注**价值**与**成本**，便于决策。

## 🥇 高优先级（高频需求，建议优先）

### 1. 订阅差分 & 变更提醒
- **价值**：订阅节点质量参差，上游时常丢节点/换 IP。当前用户无从得知"这一版和上一版差了什么"。
- **建议**：订阅交付时比对上次缓存，输出新增/删除列表；管理面板提供最近 N 次快照与差异视图。

### 2. 节点分组/标签体系
- **价值**：节点库节点多后难以按用途（游戏/流媒体/工作）取舍。
- **建议**：节点支持自定义分组与标签，订阅可按"分组 + 标签"筛选引用。

### 3. 健康检测 / 延迟测速
- **价值**：转换后节点是否可用，用户当前只能靠客户端反馈。
- **建议**：管理面板对节点做 TCP/HTTP 连通检测，标注延迟与可用性；订阅输出可排除超时节点。

### 4. 规则链可视化编辑（拖拽排序）
- **价值**：规则链逐步增多时现有 UI 只能上下移动，拖拽 + 启用/停用开关提升效率。
- **建议**：规则卡片支持拖拽排序、临时停用（保留配置）、复制规则。

## 🥈 中优先级（增强体验）

### 5. 多语言界面（i18n）
- **价值**：项目发布到 GitHub 后面向国际用户。
- **建议**：引入 i18n（如 `react-i18next` 或轻量路由方案），默认中文，提供英文面板。

### 6. 订阅示例/模板库
- **价值**：新用户学习成本高。
- **建议**：内置常见场景模板（"国内直连 + 自动选优"、"流媒体解锁"），一键填充规则链。

### 7. 输出格式扩展：TUN 模式 / Clash TUN 模板
- **价值**：部分用户需要整机代理配置。
- **建议**：支持 Clash/Mihomo TUN 模式配置导出、sing-box 完整配置（含 DNS/路由）。

### 8. 定时同步 & 自动重试
- **价值**：远程源偶尔失败，管理面板当前只支持手动重跑。
- **建议**：调度器定时拉取远程源（可配置 cron），失败保留上次成功结果并告警。

## 🥉 低优先级（锦上添花 / 长期）

### 9. 节点二维码分享
- **价值**：手机客户端扫码导入更便捷。
- **建议**：节点详情页展示二维码。

### 10. 审计日志 / 操作历史
- **价值**：多用户（或误操作）场景下有据可查。
- **建议**：记录登录、订阅创建/修改/删除、节点导入等关键操作。

### 11. 数据导出/备份（一键）
- **价值**：D1 数据迁移或灾备。
- **建议**：管理面板导出全部订阅与节点为加密 JSON；导入恢复。

### 12. 移动端优化
- **价值**：管理面板在手机上编辑体验一般。
- **建议**：针对窄屏优化表格/编辑抽屉，支持触屏长按操作。

## 🔒 安全与合规增强

### 13. 订阅访问审计
- **建议**：记录每个 token 的访问时间/来源 IP（脱敏），识别被盗用的订阅地址。

### 14. 节点凭据加密存储（可选）
- **建议**：D1 中节点密码/密钥使用 `CUTTLE_LINK_KEY` 加密存储（需要迁移时兼容旧数据）。
